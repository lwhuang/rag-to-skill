# 聊天紀錄 RAG 技能建置指引：時序分割與 VS Code 雙重定位協定

> 本指引專門用於處理**對話紀錄、通訊聊天歷程（如 LINE、Discord、Messenger、Slack 等）**或長篇時序對話的 RAG 來源。
> 聊天紀錄與一般結構化書籍不同，具備「高碎片化」、「時間跨度長」、「主題頻繁交錯跳躍」等特性，必須採用本協定進行建置與溯源。

---

## 一、核心挑戰與設計原則

一般書籍可透過目錄（TOC）與章節進行語意聚合，但聊天對話紀錄具有以下痛點：
1. **無章節結構**：話題隨時切換，難以單純按語意分章。
2. **容量巨大但單條短小**：一年份的對話動輒數萬到數十萬行，若未妥善分割會導致檢索失焦或檔案難以載入。
3. **溯源精度要求高**：使用者常需要回溯「當時是幾月幾號幾點講的」，甚至需要直接跳轉開啟該行對話查證前後語境。

為了解決上述問題，本規範確立兩大核心：**「時序分割（Temporal Chunking）」** 與 **「VS Code 雙重定位協定（Dual-Anchoring Protocol）」**。

---

## 二、時序分割協定（Temporal Chunking）

### 2.1 分割維度：以「自然月份」為基準單位
* **預設分組**：以月份 `YYYY-MM.md` 作為各 reference 檔案之切分單位（例如 `references/2023-08.md`、`references/2023-09.md`）。
* **檔名規範**：必須採用 ISO 標準的零補齊格式 `YYYY-MM.md`，以保證目錄排序時天然符合時序演進。
* **彈性調整級距**：
  * **超大量對話**（單月對話超過 8,000 行）：拆分為半月 `YYYY-MM-A.md`（1~15 日）與 `YYYY-MM-B.md`（16 日至月底）。
  * **極低量對話**（整年對話少於 1,000 行）：可提升級距以年份 `YYYY.md` 分檔。

### 2.2 Reference 檔案內文結構規範
每個時序 reference 檔案的標題與排版應標準化，按日遞增：

```markdown
# YYYY 年 MM 月 對話紀錄

> 來源本體：對話紀錄（RAG items XXX–YYY）

## YYYY/MM/DD

* [09:15] 發言者A：今天下午的會議改到三點。
* [09:16] 發言者B：收到，地點一樣在會議室A嗎？
* [09:17] 發言者A：對，會議室A。

## YYYY/MM/DD
...
```

## 三、VS Code 雙重定位協定（Dual-Anchoring Protocol）

為了讓使用者在檢索對話時，能以最快速度回溯至實際對話檔案的確切行號，產出的 Skill 回覆**必須提供雙重定位連結**。

### 3.1 雙重定位格式定義
在 AI 引用對話回答時，必須同時提供「Markdown 超連結」與「純文字絕對路徑指標」：

1. **Markdown 格式超連結（供滑鼠直接點選）**：
   * 格式：`[YYYY/MM/DD HH:mm 發言者 核心摘要](file:///絕對路徑#L<行號>)`
   * 路徑必須轉換為正斜線 `file:///C:/Users/.../references/YYYY-MM.md#L1234`。
2. **純文字絕對路徑與行號（供複製快捷跳轉，獨立一行行內程式碼）**：
   * 格式：`C:\Users\...\references\YYYY-MM.md:1234`
   * 採用 Windows 反斜線標準路徑，末尾接冒號與行號。

### 3.2 標準回覆輸出範例

```markdown
根據紀錄，你們在 2023 年 11 月確認了合作方案細節：

> * 合作確認：[2023/11/19 09:06 姿莉對話](file:///C:/Users/liwu/.agents/skills/ebook-zli69-chat/references/2023-11.md#L4178)
>   `C:\Users\liwu\.agents\skills\ebook-zli69-chat\references\2023-11.md:4178`

---
💡 **精確溯源指引**：在 VS Code 中按下 `Ctrl + P`，直接將上方的純文字路徑貼上並按 Enter 鍵，即可 100% 精確跳轉開啟至該行對話。
```

## 四、建置生成的 skill.md 鐵律

當使用本工具產生對話類型的 Skill 時，其根目錄的 `skill.md` 必須包含以下設定：

### 4.1 停用模型自動叫用
在 Frontmatter 中加入設定，避免日常對話隨機觸發大量載入：
```yaml
---
name: ebook-<name>-chat
disable-model-invocation: true
description: |
  【本技能已停用模型自動叫用，僅在使用者明確指示或手動指定時載入】
  收錄 <主角名稱> 的歷年對話紀錄與溝通細節...
---
```

### 4.2 強制注入「來源標註與回覆鐵律」
在產出的 `skill.md` 第五節必須強制規範：
1. 嚴禁任何無行號定位的模糊回覆。
2. 凡引用具體對話，必須落實**雙重定位標註**。
3. 提示末尾引導使用者使用 VS Code `Ctrl + P` 貼上跳轉。

## 五、驗證與稽核 Checklist

交付前必須執行以下檢核：

- [ ] **時序連續性檢查**：確認各月份檔案交界處無遺漏日期的訊息。
- [ ] **行號定位校驗（抽檢 5 處）**：
  隨機抽取 5 個標註行號，在 VS Code 按 `Ctrl + P` 貼上路徑與行號，確認開啟位置是否精準落在該條對話開頭。
- [ ] **雜訊清理檢查**：確認系統廣播（如加入群組、通話取消、純貼圖空物件）已被適當過濾或標記，不干擾語意檢索。
